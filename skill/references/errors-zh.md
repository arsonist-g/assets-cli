# 退出码与失败

命令以非零退出、而下一步该做什么并不明显时读这份。

## 封闭的完整集合

| 退出码 | 含义 | 动作 |
|---|---|---|
| 0 | 成功 | 读 stdout |
| 2 | 用法错误，或引用的平台、账号、变量没登记过 | 改正参数，或先把缺的平台、账号建出来。原样重试没有用 |
| 3 | 某一段违反字符集或 64 字符上限，或值是空的 | 改正参数。原样重试没有用 |
| 4 | 注册表或数据文件读不动、写不动，或台账与注册表不一致 | 先看文案：下面两种情况动作不同 |
| 5 | 名字撞车，或注册表里有一个本工具没声明的变量 | 文案里点了名，换个名字或交给人处理 |
| 6 | 值或整个环境块的总量超预算 | 把值改短，或在 GUI 里腾出空间 |
| 7 | `assets doctor` 有未通过的检查 | 明细列里写了是哪一项、怎么修 |

退出 4 装着两种情况，靠文案区分：

- 文案里点了某个变量名，说明台账与注册表对这个变量不一致。重试没有用；用 `assets var set` 把值补回去，再重复那条命令。
- 其它 4 是存储故障。重试一次，然后跑 `assets doctor`。

只有这一种情况值得原样重试。2、3、5 在参数或名字不变之前会一模一样地重复，6 需要更短的值，7 需要按明细里写的那一项去修。

## 实际会遇到的文案

| 文案 | 退出码 | 怎么办 |
|---|---|---|
| `平台不存在：<名称>` | 2 | 该平台从未登记过，或名字拼写不同。没有模糊匹配，要么改名字要么先把平台建出来。`var set` 与两条 `rename` 打的是这个裸形式 |
| `平台不存在：<名称>（用 assets list 看已登记的平台）` | 2 | 同一种情况，`list` 的说法 |
| `平台不存在：<名称>（先用 assets platform add 建平台）` | 2 | 账号需要一个归属，所以先建平台。`account add` 的说法 |
| `平台 <名称> 下没有条目：<别名>` | 2 | 这个别名不属于该平台，而 `var set --account` 不会把它建出来 |
| `--account 必须与 --platform 同用` | 2 | 两个一起给，或只给 `--platform` |
| `平台名只能包含 A-Z a-z 0-9 和 _：<值>` | 3 | 别名和术语同一套字符集；常见起因是连字符 |
| `别名过长：最多 64 个字符，当前 <n>` | 3 | 把这一段改短 |
| `值不能为空：不声明即不存在，空值会让变量名没有意义` | 3 | 让他在 GUI 里删，而不是存一个空值 |
| `值过长：超过单个用户级变量上限（32767 字符）` | 6 | 把值改短 |
| `预算提示：环境块已用 <n> / 262144 字符（<p>%），接近上限` | 0 | 一次成功的写入上带的提示，出现在预算的 80% 及以上。此时还没有出错；越界的那次写入才会以退出码 6 失败 |
| `平台已存在：<名称>（重名检测不区分大小写）` | 5 | 这个名字已存在，只是大小写不同 |
| `注册表里已有同名变量 <名称>，但台账里没有对应声明；为免覆盖手工创建的变量，拒绝写入` | 5 | 名字被一个手工创建的或外来的变量占着。是否接管（用 GUI）或改名，由人决定 |
| `台账与注册表不一致：<名称> 在注册表里没有值，已拒绝改名` | 4 | 这是脱节，不是存储故障。用 `assets var set` 把值补回去，再重复改名。工具宁可不改名，也不搬一条它无法核对的声明 |
